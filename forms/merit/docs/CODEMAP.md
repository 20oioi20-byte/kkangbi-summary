# CODEMAP.md — forms/merit (본부장표창 공적조서) 코드 지도

> 이 양식만 작업할 때는 이 문서와 `forms/merit/` 안의 파일만 열면 된다.
> 다른 양식(`forms/weekly`, `forms/makeup`)은 열지 않는다.
> **최종 갱신:** 2026-07-29

---

## 1. 이 양식이 하는 일

대상자별로 공적조서 1건씩 작성한다. 담당자가 **작성 방향성 + 실적 메모(두서없이)** 를 적으면
AI가 3개 섹션 초안을 만들고, 사용자가 확인·수정한 뒤 **원본 .doc 양식과 동일한 서식의 워드 파일**로
저장한다.

| 섹션 | 성격 (서로 중복되게 쓰지 않는다) |
|---|---|
| 1. 실적 요약 | **무엇을** 이뤄냈는가 — 결과·성과 중심 압축 |
| 2. 실적 달성을 위한 활동 | **어떻게** 해냈는가 — 구체적 실행과 효과(분량 가장 많음) |
| 3. 핵심가치 실천/기타사항 | 회사 핵심가치 기준으로 **태도·자세** 관점 |

---

## 2. 파일 지도

| 무엇을 고칠 때 | 파일 | 핵심 |
|---|---|---|
| 저장 키·상태·팀원 명단 로딩 | `js/merit-state.js` | `loadMeritState`, `saveCurrent`, `deleteRecord`, `mutateIndex` |
| 화면·AI 초안 호출 | `js/merit-app.js` | `renderList`, `renderEditor`, `generateMeritDraft`, `collectFormIntoRecord` |
| **워드(.docx) 생성 서식** | `js/merit-docx.js` | `buildMeritDocxBlob`, `MERIT_GRID`, `mSpans` |
| 화면 스타일 | `css/merit.css` | — |
| AI 프롬프트·모델 | `../../api/ai-merit-draft.js` | 섹션별 역할·형식 규칙·핵심가치 |

스크립트 로드 순서(= `index.html`): kv-client → auth → logo-data → merit-state → merit-docx → merit-app.

## 3. 저장 키

허브 규칙(`docs/HUB-CODEMAP.md` §5) "엔티티 1건 = 저장 키 1개"를 따른다.

| 데이터 | 키 | 비고 |
|---|---|---|
| 공적조서 목록 | `ktis_v11__merit_index` | **메타데이터만**(id/성명/직급/소속/수정일). 본문 절대 넣지 말 것 |
| 공적조서 1건 | `ktis_v11__merit__rec__{id}` | 전체 내용 |
| (읽기 전용) 팀원 명단 | `ktis_v11__weekly_members` | 주간보고 양식 소유. **이 양식에서 쓰지 않는다** |

목록은 `mutateIndex()`로만 갱신한다 — 저장 직전 서버 최신값을 다시 읽고 내 변경만 얹는 방식.
브라우저를 오래 켜둔 사람이 옛 스냅샷을 통째로 덮어써 남의 항목을 지우는 사고를 막기 위함.

## 4. 워드 서식 — 원본 .doc에서 실측한 값 (임의로 바꾸지 말 것)

원본 양식(`공적조서 양식(26년 상반기)….doc`)을 Word COM으로 열어 실측한 값이다.
생성 결과를 다시 Word로 열어 **아래 항목이 모두 일치함을 확인**했다(2026-07-29).

| 항목 | 값 |
|---|---|
| 용지 여백(pt) | 위 70.9 / 아래 63.8 / 왼 49.7 / 오른 63.7 → twips 1418/1276/994/1274 |
| 제목 "공 적 조 서" | 맑은 고딕 **20pt 굵게 가운데** |
| "*공적기간: …" | 맑은 고딕 **10pt 오른쪽** |
| 표 본문·라벨 | 맑은 고딕 **11pt** (라벨은 굵게 가운데) |
| 라벨칸 채우기색 | **D9D9D9** (Word 실측값 14277081) |
| 표 전체 폭 | **10260 dxa** (=513pt) |
| 행 구성 | 10행 / 칸수 6,2,2,1,1,1,1,1,1,7 |
| 인적사항 칸 폭 | 1280,1900,1320,2060,1300,2400 (dxa) |
| 확인자 칸 폭 | 1040,760,3460,1300,1420,800,1480 (dxa) |
| 로고 | kt is, 헤더 우측 상단. 원본 내장 PNG가 `shared/logo-data.js`와 동일 이미지(1641×987)임을 확인 |
| 글머리표 | 대분류 `( `, 하위 `- ` — **심볼폰트가 아니라 맑은 고딕의 일반 문자 `(`**(U+0028)임을 원본에서 확인 |

### tblGrid를 함부로 고치지 말 것
Word 표는 **모든 행이 하나의 공통 `tblGrid`를 `gridSpan`으로 나눠 쓰는** 구조다. 이 양식은 행마다
칸 수가 다르므로(6칸 / 2칸 / 1칸 / 7칸), 두 레이아웃의 칸 경계를 모두 포함하는 **마스터 그리드 11칸**
(`MERIT_GRID`)을 만들어 두고 `mSpans()`가 각 칸의 span을 자동 계산한다.
칸 폭을 바꾸면 `MERIT_GRID`도 같이 다시 계산해야 한다 — **행별 gridSpan 합계가 11이 아니면 Word에서
표가 깨진다**(실제로 이 버그를 만들었다가 검증에서 잡았다).

> 값칸 배경은 원본이 rows1~9는 "자동(무지정)", row10만 흰색(FFFFFF)으로 섞여 있는데,
> 이 파일은 전부 FFFFFF로 통일했다 — 렌더링 결과는 동일하다(둘 다 흰색).

## 5. AI 초안 (`api/ai-merit-draft.js`)

- 저장소를 조회하지 않는다 — 근거 자료를 사용자가 직접 입력하는 구조라 `SUPABASE_*`가 필요 없다.
- 호출 방식은 `api/ai-weekly-draft.js`와 **완전히 동일**: 서강대 API Gateway 우선 → 실패 시 Anthropic
  직접호출로 자동 폴백. 한쪽만 고치고 다른 쪽을 안 고치면 모델/폴백 규칙이 어긋나니 같이 볼 것.
- 응답은 `===실적요약===` / `===활동===` / `===핵심가치===` 마커로 나눠 파싱한다 —
  프롬프트에서 이 마커 문구를 바꾸면 파싱이 깨지니 같이 맞출 것.
- 마커가 하나도 안 잡히면 전체를 1번 섹션에 넣어 사용자가 직접 나눌 수 있게 한다(실패로 만들지 않음).
- **필요 환경변수**: `ANTHROPIC_API_KEY`(필수), `CLAUDE_MODEL`(선택, 기본 `claude-sonnet-4-6`),
  `SOGANG_GATEWAY_KEY`(선택 — 있으면 게이트웨이 우선). 주간보고와 같은 값을 공유한다.

## 6. 검증 방법 (다음에 고칠 때도 이렇게 확인할 것)

1. 로컬 모의 서버로 화면·저장·삭제·AI 초안 라운드트립 확인
2. `scratchpad/gen_merit_docx.mjs` 패턴으로 브라우저 없이 .docx를 파일로 생성
3. Word COM으로 **생성물과 원본을 각각 열어** 여백/폰트/크기/칸폭/배경색/행구성을 표로 비교
   - 주의: Word COM으로 레거시 `.doc`를 열 때 `~$…` 잠금 파일이 남아있으면 무한 대기한다.
     열리지 않으면 먼저 `~$` 파일을 지우고 `Unblock-File`로 다운로드 차단을 해제할 것.
