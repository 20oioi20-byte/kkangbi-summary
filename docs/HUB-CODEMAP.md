# HUB-CODEMAP.md — 깡비서 자료취합 허브 라우팅 지도

> **이 문서는 "어디로 가야 하는지"만 알려준다. 각 양식의 내부 함수/로직은 절대 여기 적지 않는다.**
> 요청받은 작업이 특정 양식에 관한 것이면, 아래 표에서 폴더를 찾아 그 폴더의 `docs/CODEMAP.md`만 열고
> 이 저장소의 다른 `forms/*` 폴더는 열지 않는다. 새 양식을 추가했으면 이 표에 한 줄 추가할 것.
> **최종 갱신:** 2026-07-25

## 2. 허브 공용(shared/) — 라우팅표

| 파일 | 역할 | 고칠 때 주의 |
|---|---|---|
| `shared/kv-client.js` | 서버 저장 통신(`apiGet/apiSet/apiList/apiDelete/apiSetMany/apiDeleteMany`) — 청크 분할·적응형 크기·백오프 재시도 내장(§5) | 모든 양식이 씀 — 여기 고치면 전 양식 영향, 신중히 |
| `shared/auth.js` | 허브 공용 비밀번호 화면잠금 | 모든 양식이 씀 |
| `shared/logo-data.js` | kt is 로고 base64 | 로고 자체가 바뀔 때만 |
| `shared/base.css` | 버튼/카드/배지/잠금화면 등 최소 공통 모양(색상 아님) | 색상은 넣지 않는다 — 자세한 건 `shared/docs/SHARED-CODEMAP.md` |
| `api/storage.js` | Supabase(`rpt_kv`) 프록시, service_role 전용 | 모든 양식 공용 API — 새 양식마다 API 새로 만들지 않는다 |

## 4. 새 양식을 추가했다면

1. `forms/{slug}/` 폴더 생성 (`index.html`, `css/`, `js/`, `docs/CODEMAP.md`, `docs/README.md`)
2. 저장 키는 `ktis_v11__{slug}_*`로, 다른 양식과 절대 겹치지 않게
3. 루트 `index.html`의 `HUB_FORMS` 배열에 카드 추가
4. 이 문서(§1 표)에 한 줄 추가, 상태를 "배포됨"으로 변경
5. 저장 설계는 §5를 따를 것 — 특히 "목록 전체를 배열째로 한 키에" 저장하는 패턴 금지

## 5. 저장 프로토콜 — 회사망(불안정/차단성 네트워크) 내성 (2026-07-26 적용)

> 근거 문서: `~/dev-standards/network-resilient-storage.md` (사내 필수 표준). `kkangbi-calendar` 프로젝트에서
> 회사망이 저장 요청을 예고 없이 차단한 실사고가 반복된 뒤 만들어진 체크리스트.

- `shared/kv-client.js`가 **모든 양식 공통으로** 다음을 이미 처리한다 — 새 양식을 만들 때 이 로직을 직접 구현할 필요 없음:
  - 값이 크면 자동 청크 분할(`{key}__chunk__{i}` + 매니페스트), UTF-16 서로게이트 쌍 안전 분할
  - 실패 시 "안전 크기"를 스스로 줄여가며 재시도(고정 숫자를 코드에 박지 않음), 바닥(8KB)까지 줄여도 안 되면 백오프 재시도
  - 알아낸 안전 크기는 `localStorage`(`kkangbi_kv_safe_size_v1`)에 기억, 성공이 이어지면 천천히 회복
  - 실패로 확정하기 전 서버 재조회로 "응답만 유실된 성공"을 오탐하지 않음
  - `apiSetMany`/`apiDeleteMany`로 여러 항목을 배치 전송(요청 개수 자체를 줄임)
- 새 양식을 설계할 때 지켜야 하는 것(이건 각 양식 코드가 직접 지켜야 함, kv-client가 대신 안 해줌):
  - **엔티티 1건 = 저장 키 1개.** "배열 전체를 한 키에 통째로" 저장하지 않는다 — 데이터가 쌓일수록(첨부파일, 이력 등) 이 패턴이 페이로드 크기 차단의 직접 원인이 된다. 실제로 `forms/weekly`의 자료보관함(워드 파일 base64, 최대 30개)이 이 패턴이었다가 이번에 항목별 키로 분리됐다 — `forms/weekly/docs/CODEMAP.md` §5 참고.
  - 저장 구조를 바꾸는 마이그레이션을 할 땐 구 키를 즉시 지우지 말고, 가능하면 신·구 형식을 병합해서 읽다가 신 형식 저장이 안정된 뒤에 정리한다(이번 주간보고 마이그레이션 때는 이 원칙을 못 지켰음 — 다음부터는 지킬 것).
- 적대적 네트워크(요청 크기 제한을 강제로 건 가짜 서버) 통합 테스트로 청크/적응형/배치/삭제 정리가 실제로 수렴하는지 검증된 상태(2026-07-26, 이 세션의 스크래치패드 `mock-server.js` 패턴).
